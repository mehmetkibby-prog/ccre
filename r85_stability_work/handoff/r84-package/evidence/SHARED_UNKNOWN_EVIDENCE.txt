WHAT WAS RULED OUT AS A JUSTIFIED PATCH
No evidence establishes that these incidents had a valid not_executed response,
a dropped certified rollback proof, or a particular missing classification code.
Adding a guessed code to the shared rollback allowlist, using missing receipt as
rollback proof, shortening expiry, unlocking the terminal, or disabling the
global_world_busy guard would not be a supported root-cause fix. No such change
was made. The 8192-character shared lease bound is already in current source,
enabled by default; live environment overrides have not been inspected.

SEPARATE PROVEN DEFECT
The recovery completion race is independently reproduced and has an isolated narrow
candidate, source pins, and 30 passing controlled interleaving cases in this folder.
It can leave recoveringWorld true after a late fault coalesces with an already
completed recovery promise. A separate actual-ended/requestRecovery harness also
reproduces a fresh CH1 owner exiting while CH2 boots: its notification coalesces,
and old code finishes with CH1 offline and no retry. The current isolated candidate
pins/revalidates every newly booted owner before jobs/ready publication; a lost
generation enters the existing fenced failure/retry policy. Neither defect is
proven to be the cause of either original writer error or the full reported lag
duration. Fixtures mock OS exit/boot and DB durability boundaries.
See RECOVERY_FINALIZATION_FINDINGS.txt for exact evidence and limits.
